# 開票自檢：`scripts/ticket-check.sh`

開完一批票就在本機跑一次（`to-tickets` 第 7 節）。退出碼 1＝這批票還沒開完：照 NG 行修好再跑，直到 0。repo 裝了開票自檢 workflow 時，Actions 在票開出時另跑一次（下面「Actions 上跑」）。

```
scripts/ticket-check.sh <owner/repo> [票號 ...]
```

- 給了票號只查那幾張（標籤格、錨點、做完能展示什麼都只查那幾張）；不給就查整個 repo。票號不在票清單裡 ⇒ `??`。票號的前導零不算（`012`＝12）。
- 只讀：只呼叫 GitHub 的讀取 API，不改任何票、標籤或設定。票內文一個 repo 一次 GraphQL 拿齊，不逐票讀。
- 退出碼：`0` 全過；`1` 有 NG；`2` 參數用錯。跑完一定印 `--` 開頭的總結；沒有總結＝沒跑完，退出碼不是檢查結果。
- 測試：`tests/test-ticket-check.sh`（只對假 gh 跑）。
- 錨點 SHA 問不到的也算進總結的「問不到 N 處」。

## Actions 上跑

`skills/setup/references/ticket-check-workflow.yml` 是範本，`setup` 問過、答「裝」才裝進 repo。

- 觸發：`issues: opened`。只查 repo 設定「只檢查誰開的票」那個帳號開的票：外部帳號用範本開的票整張不查、不留言。
- plugin 取這個公開 repo 的 `main`（與各機器 autoUpdate 同一條信任線），跑 `ticket-check.sh <repo> <剛開的票號>`。
- 全過不留言。有 `NG` 列在「NG」；`??` 與 `!!` 列在「未驗」，不寫成 NG；沒印總結＝沒跑完，留言註明不算數、job 判紅。
- **限制**：token 是這個 repo 的 `GITHUB_TOKEN`（`issues: write`、`contents: read`），讀不到別的私有 repo。錨點指到別的私有 repo 時，那顆 SHA 問不到，落在「未驗」——要驗它，在本機用擁有者的權限重跑。所以它是補網，不取代開票的人在本機跑的那一次。
- Actions 額度用完時 job 不跑（not started），票上沒有留言，看起來和全過一樣。

## 三態

| 開頭 | 意思 | 算不算紅 |
|---|---|---|
| `NG` | 問到了，而且不對 | 算，退出碼 1 |
| `??` | 沒問到：離線、沒權限、限流、repo 設定讀不到 | 不算，但一定印出來 |
| （空白） | 問到了，而且對 | 不算 |
| `!!` | 兩把尺數出來對不上（例：錨點形狀幾條、抽得出網址幾條），有東西沒被驗到 | 不算，但要看 |
| `skip` | 這張票不是施工票，不查錨點與格 9 | 不算 |

UNKNOWN 不算紅，是因為離線時永遠紅的燈等於沒有燈。看到 `??` 要去補上讀不到的那一樣（權限、設定），不是忽略。

## 從 repo 設定讀的值

repo 特有的值讀目標 repo 的 `docs/agents/github.md`（「機器讀的欄位」區塊，格式見 `skills/setup/references/repo-config-template.md`），腳本不寫死任何 repo 或帳號。值去頭尾空白，帳號比對不分大小寫。

| 欄位 | 用在 | 讀不到 |
|---|---|---|
| 只檢查誰開的票 | 標籤格（格 1、2、6）只查這個帳號開的票（別人的票只留言、不改標籤） | 環境變數 `LABEL_OWNER` 可覆寫；兩者都沒有 ⇒ 標籤格整個印 `??`，錨點與格 9 照跑。有開著的票、卻沒有一張是這個帳號開的 ⇒ `??`（帳號多半設錯） |

值寫 `見 <owner>/<repo>`（專案層的事寫在放票的 repo）時當成讀不到：票不在這個 repo，對放票的那個 repo 跑。

repo 沒有任何類型標籤 ⇒ 視為還沒套用標籤制度，整個略過標籤檢查（印一行說明），否則每張票都缺類型而整片紅。

## 哪些票算施工票

標題前綴是 `[SPEC]`（或以 `SPEC` 開頭）、`[外審]`，或標題裡有「指揮台」的票不是施工票：不查錨點與格 9，印一行 `skip`。只看前綴，標題中間提到 SPEC 的施工票照查。不另外維護前綴清單：其他沒有程式碼錨點的票（開票、決定、查證…）在錨點段寫一行 `- 無：<理由>`（見下面「錨點」）。

標籤格的票種另外判（`references/labels.md` 第七節）：只認 SPEC 與「協作指揮台」開頭兩個例外，其他一律一般票。`[外審]` 不查錨點，但標籤照查。

## 每格查什麼

### 錨點（開著的施工票）

| 查什麼 | 判紅條件 |
|---|---|
| 錨點段 | 沒有一行 `##` 開頭、含「錨點」的段落 |
| SHA 固定連結 | 錨點段裡沒有任何釘了 40 碼 SHA 的檔案連結（`/blob/`、`/tree/`、`/blame/`、`/raw/`，或 `raw.githubusercontent.com/<owner>/<repo>/<SHA>/…`；host 不分大小寫、可帶 `www.`；剛好 40 碼小寫十六進位），也沒有「無」那一行 |
| 錨點「無」 | 錨點段沒有 SHA 連結、只寫一行 `- 無：<理由>`（半形或全形冒號）⇒ OK，印出理由。理由是空的、只有空白（含全形空白）或只有 `-` 這類符號 ⇒ NG；那一行在程式碼圍欄裡不算。寫了「無」又放了沒釘 SHA 的檔案連結（`blob/main/…`）⇒ NG。完全沒有錨點段照樣 NG |
| 沒釘 SHA 的檔案連結 | 有 SHA 連結、又有 `blob/main/…` 這類連結 ⇒ 那幾條印 `!!`（沒被驗存在） |
| 那顆 SHA 存在 | 逐顆問 GitHub，回 422（No commit found：repo 讀得到、SHA 不在）⇒ NG；404 與其他失敗 ⇒ `??`（沒權限讀的私有 repo 也回 404，分不出「不在」） |

形狀對不代表那顆存在：40 碼形狀完美、連結點下去 404 的錨點，只有逐顆問才抓得到。開票時 SHA 一律用 `git rev-parse` 取，不要從短碼補。

錨點段在哪、哪些連結算錨點、連結結尾怎麼剝、「- 無：<理由>」怎麼認，只寫在 `ticket-check.sh` 的 `anchor_section`／`anchor_parse` 一處。

### 標籤格 1、2、6（只查「只檢查誰開的票」那個帳號開的票）

| 格 | 查什麼 | 判紅條件 | 查哪些票 |
|---|---|---|---|
| 1 | 必掛三組 | 一般票少了類型、優先、驗證任何一組；SPEC 少了類型或優先；協調類全免 | 開著的 |
| 2 | 單選 | 類型、優先、驗證任一組掛了兩個以上（逐字比對標籤名） | 開著＋已關 |
| 6 | 衍生掛得對 | 掛了 `衍生`，上層卻不是 SPEC 或沒有上層 | 開著的 |

- **已關的票只查格 2**：舊票沒有類型、優先，查格 1 會整片紅。
- 格號沿用原本的編號，沒有重排：格 3（有人在做或待驗證，卻沒掛機器標籤）與格 4（已關的票還掛著機器標籤）移到使用端的每日稽核（照私有擴充），不在這支。

### 格 9：做完能展示什麼（開著的施工票）

| 判紅條件 |
|---|
| 沒有標題含「做完能展示什麼」的段落 |
| 那段到下一個同級或更高級的標題之間只有空白或只有子標題 |

這一段寫「做完之後能拿出來給人看的東西」，空白就擋：寫不出來，代表這張票的完成定義還沒想清楚。段落底下可以有子標題，子標題底下的內容算數。

## 改這支之前

- 每格判準都有測試釘住；改判準就改測試，並把那一格的突變（`tests/mutations-ticket-check.txt`，一行一顆 sed）跑一次：改回壞的樣子要紅、還原要綠。
- 新增一格：判準寫成可以被 source 的函式，在測試加一張「從好票故意做壞一處」的陽性對照；好票先要是綠的，壞票才有意義。
