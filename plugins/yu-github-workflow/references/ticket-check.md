# 開票自檢：`scripts/ticket-check.sh`

開完一批票就跑一次。退出碼 1＝這批票還沒開完：照 NG 行修好再跑，直到 0。

```
scripts/ticket-check.sh <owner/repo> [票號 ...]
```

- 給了票號只查那幾張（標籤格、格 5～9、錨點都只查那幾張）；不給就查整個 repo。票號不在票清單裡 ⇒ `??`。票號的前導零不算（`012`＝12）。
- 只讀：只呼叫 GitHub 的讀取 API，不改任何票、標籤或設定。票內文一個 repo 一次 GraphQL 拿齊，不逐票讀。
- 退出碼：`0` 全過；`1` 有 NG；`2` 參數用錯。跑完一定印 `--` 開頭的總結；沒有總結＝沒跑完，退出碼不是檢查結果。
- 測試：`tests/test-ticket-check.sh`（只對假 gh 跑）。
- 用 `gh issue create` 開完票，PostToolUse hook（`scripts/hook-post-bash.sh`）只取 `gh issue create` 印出的那一行票網址（整行就是網址），只對那張票跑一次，NG 放進對話；沒有那一行就不跑，並明講沒跑；自檢沒印總結就明講沒跑完；退出碼 0 但有 `??` 時講「沒有 NG，但有 N 處讀不到」，不寫全過。整行票網址比指令裡的開票次數多、指令裡又沒有迴圈（同一次 Bash 裡別的指令也印了票網址）⇒ 分不出哪張是剛開的，不跑、明講。

## 三態

| 開頭 | 意思 | 算不算紅 |
|---|---|---|
| `NG` | 問到了，而且不對 | 算，退出碼 1 |
| `??` | 沒問到：離線、沒權限、限流、repo 設定讀不到 | 不算，但一定印出來 |
| （空白） | 問到了，而且對 | 不算 |
| `!!` | 兩把尺數出來對不上（例：錨點形狀幾條、抽得出網址幾條），有東西沒被驗到 | 不算，但要看 |
| `skip` | 這張票不是施工票，不查錨點與格 9 | 不算 |

UNKNOWN 不算紅，是因為離線時永遠紅的燈等於沒有燈。看到 `??` 要去補上讀不到的那一樣（權限、設定），不是忽略。

## 從 repo 設定讀的值

repo 特有的值一律讀目標 repo 的 `docs/agents/github.md`（「機器讀的欄位」區塊，格式見 `skills/setup/references/repo-config-template.md`），腳本不寫死任何 repo、帳號或 Project。值去頭尾空白，機器標籤名逐個去空白，帳號比對不分大小寫。

| 欄位 | 用在 | 讀不到 |
|---|---|---|
| 只檢查誰開的票 | 標籤格 1～8 只查這個帳號開的票（別人的票只留言、不改標籤） | 環境變數 `LABEL_OWNER` 可覆寫；兩者都沒有 ⇒ 標籤格整個印 `??`，錨點與格 9 照跑。有開著的票、卻沒有一張是這個帳號開的 ⇒ `??`（帳號多半設錯） |
| 施工狀態記法 | 格 3、格 8 | 格 3、8 不判，印一行 `??`（格 4 照判） |
| Project 所在 | 格 3、格 8（只在 `project` 記法） | 格 3、8 的 Project 判斷印 `??` |
| 機器標籤名 | 格 3、格 4 | 格 3、4 不判，印一行 `??`（格 8 照判）；值是 `無` ⇒ 這個 repo 不用機器標籤，格 3、4 不判 |

兩個都讀不到 ⇒ 那一行寫「格 3、4、8 不判」。

值寫 `見 <owner>/<repo>`（專案層的事寫在放票的 repo）時當成讀不到：票不在這個 repo，對放票的那個 repo 跑。

repo 沒有任何類型標籤 ⇒ 視為還沒套用標籤制度，整個略過標籤檢查（印一行說明），否則每張票都缺類型而整片紅。

## 哪些票算施工票

標題前綴是 `[SPEC]`（或以 `SPEC` 開頭）、`[外審]`，或標題裡有「指揮台」的票不是施工票：不查錨點與格 9，印一行 `skip`。只看前綴，標題中間提到 SPEC 的施工票照查。不另外維護前綴清單：其他沒有程式碼錨點的票（開票、決定、查證…）在錨點段寫一行 `- 無：<理由>`（見下面「錨點」）。

標籤格的票種另外判（`references/labels.md` 第七節）：只認 SPEC 與「協作指揮台」開頭兩個例外，其他一律一般票。`[外審]` 不查錨點，但標籤照查。

## 每格查什麼

### 錨點（開著的施工票）

| 查什麼 | 判紅條件 |
|---|---|
| 錨點段 | 沒有一行 `##` 開頭、含「錨點」的段落 |
| SHA 固定連結 | 錨點段裡沒有任何 `/blob/<40 碼>` 或 `/tree/<40 碼>` 的連結（剛好 40 碼，後面接的不是十六進位字元），也沒有「無」那一行 |
| 錨點「無」 | 錨點段沒有 SHA 連結、只寫一行 `- 無：<理由>`（半形或全形冒號）⇒ OK，印出理由；理由是空的 ⇒ NG。完全沒有錨點段照樣 NG |
| 那顆 SHA 存在 | 逐顆問 GitHub，回 422（No commit found：repo 讀得到、SHA 不在）⇒ NG；404 與其他失敗 ⇒ `??`（沒權限讀的私有 repo 也回 404，分不出「不在」） |

形狀對不代表那顆存在：40 碼形狀完美、連結點下去 404 的錨點，只有逐顆問才抓得到。開票時 SHA 一律用 `git rev-parse` 取，不要從短碼補。

### 標籤格 1～8（只查「只檢查誰開的票」那個帳號開的票）

| 格 | 查什麼 | 判紅條件 | 查哪些票 |
|---|---|---|---|
| 1 | 必掛三組 | 一般票少了類型、優先、驗證任何一組；SPEC 少了類型或優先；協調類全免 | 開著的 |
| 2 | 單選 | 類型、優先、驗證任一組掛了兩個以上（逐字比對標籤名） | 開著＋已關 |
| 3 | 找得到人 | 有人在做或待驗證，卻沒掛機器標籤。「有人在做」：`labels` 記法看 `施工中`／`待驗證` 標籤；`project` 記法看 Status 是 `In Progress`、`施工中` 或 `待驗證` | 開著的 |
| 4 | 關票清乾淨 | 已關的票還掛著機器標籤 | 已關的 |
| 5 | 不驗自己的票 | 驗證署名與施工署名的 session 部分相同（同一個對話自己驗、驗自己派的子代理、自己派的兩個子代理一施工一驗證） | 開著的 |
| 6 | 衍生掛得對 | 掛了 `衍生`，上層卻不是 SPEC 或沒有上層 | 開著的 |
| 7 | 合併會不會誤關票 | 票上有合併後的步驟（判法只有一處：`scripts/lib/after-merge-step.sh`，與 `pr-risk.sh` 共用），卻有開著的 PR 會在合併時自動關它 | 開著的 |
| 8 | 狀態只有一處 | `project` 記法的 repo：開著的票不在 Project 裡，或還掛著 `施工中`／`待驗證`。`labels` 記法不查 | 開著的 |

- **已關的票只查格 2、4**：舊票沒有類型、優先，查格 1 會整片紅。
- **格 5 認兩種署名**（欄位用全形 `｜` 分隔）：
  - 新：`角色｜機器｜執行者｜分支`（第 3 欄是執行者，`references/labels.md` 第三節）。
  - 舊：`角色軌｜機器｜軌號｜執行者｜分支`（角色以「軌」結尾，第 4 欄是執行者）。進行中的工作還有人用舊格式。
  - 執行者是 `session <id>` 或 `agent-<id>@<派它的 session id>`；比的是 session 部分（`session` 後的 id、`@` 後的 id），前綴相同就視為同一個。
  - 多則驗證署名：任一則判得出自驗就 NG，不被讀不出執行者的那一則蓋掉；沒有 NG、又有讀不出的 ⇒ `??`。
  - 只看每則留言的最後一個非空行。署名前面的 markdown 修飾（`>`、`**`、`*`、`_`、空白）先去掉再認；去掉後開頭仍不是署名、但行內有「🔍 驗證」⇒ 算一則讀不出執行者的驗證署名（`??`），不當成沒有驗證署名。
- **格 7 的「會關它的 PR」取兩個來源的聯集**：
  - GitHub 原生的關聯（PR 內文寫關閉關鍵字，或 PR 從 `gh issue develop` 開的分支）。
  - 整合 PR：開著、目標是預設分支的 PR，內文用關閉關鍵字（`close`、`fix`、`resolve` 各種時態）指到這張票。票寫 `#N`、`owner/repo#N` 或票的網址都算。`Refs` 不算；code span 與 fenced code block（三個以上的 `` ` `` 或 `~` 圍起來的行；關上的圍欄要同一種字元、長度不少於開頭）裡的關鍵字 GitHub 不認，也不算；指到別的 repo 的不算。
  - 修法：PR 內文改寫 `Refs`；合併後做完步驟，由指揮台關票。
- **格 8 在 `project` 記法下，每張開著的票都該在 Project 裡**：不在＝沒有 Status，施工狀態沒有地方記。

### 格 9：做完能展示什麼（開著的施工票）

| 判紅條件 |
|---|
| 沒有標題含「做完能展示什麼」的段落 |
| 那段到下一個同級或更高級的標題之間只有空白或只有子標題 |

這一段寫「做完之後能拿出來給人看的東西」，空白就擋：寫不出來，代表這張票的完成定義還沒想清楚。段落底下可以有子標題，子標題底下的內容算數。

- 每格判準都有測試釘住；改判準就改測試，並把那一格的突變（`tests/mutations-ticket-check.txt`，一行一顆 sed）跑一次：改回壞的樣子要紅、還原要綠。
