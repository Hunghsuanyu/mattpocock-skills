# 私有擴充

這個 plugin 是公開的，只放通用規則。各人自己的補充（內部頻道、私有腳本的位置、只適用自己環境的步驟）放在 plugin 以外的一個目錄，由一個環境變數指過來。plugin 本身不寫死任何本機路徑。

## 設定

| 項目 | 規則 |
|---|---|
| 環境變數 | `GITHUB_WORKFLOW_PRIVATE_DIR`，值是一個目錄的絕對路徑 |
| 檔名 | `<skill 名>.md`，一支 skill 一個檔；skill 名就是 `SKILL.md` frontmatter 的 `name` |
| 沒設變數 | 正常情形。每支 skill 回報「未設定」後照本體做 |

## 每支 skill 開頭怎麼讀

三步，每支 skill 都一樣，不要改寫、不要憑印象判斷變數有沒有設：

1. 用 Bash 跑這一條，逐字照抄：`printenv GITHUB_WORKFLOW_PRIVATE_DIR`
   - `printenv` 退出碼 1 且沒有輸出＝未設定；其他情況（被權限擋、工具錯誤、沒跑成）→ 停下告訴擁有者，不當成未設定。
2. 輸出是空的（變數沒設）→ 回報「私有擴充：未設定」，照本體做。
3. 有值 → 用 Read 讀 `<值>/<skill 名>.md`。
   - 讀到 → 回報「私有擴充：已讀 <檔名>」，檔案內容當成這支 skill 的補充規則，與本體一起遵守。
   - 讀不到（目錄不存在或沒有這個檔）→ 停下來告訴擁有者讀不到哪個路徑，**不要照本體繼續**。設了變數卻讀不到，多半是路徑或檔名寫錯，照本體做會讓補充規則靜默失效。

## 補充只能加，不能推翻

- 補充可以加步驟、加檢查、指定自己環境的工具或頻道。
- 補充不能刪掉或放寬本體的任何一步。本體寫「必須」的，補充不能改成「可以不用」。
- 兩者衝突時停下來，把衝突的兩句並列給擁有者看，由擁有者決定；不要自己挑一邊。

## 開 PR 的私有掃描（`pr-scan.sh`）

`pr` skill 在公開 repo 開 PR 前，把「標題＋換行＋內文」交給私有目錄的 `pr-scan.sh` 掃一次，沒過不開。

| 項目 | 規則 |
|---|---|
| 位置 | `<GITHUB_WORKFLOW_PRIVATE_DIR>/pr-scan.sh`，用 `bash` 執行，不必設執行權限 |
| 輸入 | 標準輸入是「標題＋換行＋內文」 |
| 輸出 | 退出碼 0＝過；非 0＝沒過、不開 PR。原因印到標準錯誤，原樣轉給使用者看 |

- 私有掃描用來加自己環境才知道的東西（例如內部 repo 名、人名、主機名）；開 PR 的人照 `pr` 第 5 節自己遮蔽那一遍照做，不因為有掃描就省掉。
- 私有 repo 不掃。

## skill 內文怎麼指到 plugin 自己的檔

`SKILL.md` 內文寫 `${CLAUDE_PLUGIN_ROOT}/<相對路徑>`，載入時會被換成這個 plugin 的絕對路徑（`${CLAUDE_PLUGIN_DATA}` 也一樣會被換掉）。其他環境變數（包括 `GITHUB_WORKFLOW_PRIVATE_DIR`）不會被替換，所以照上面第 1 步用 `printenv` 讀。
