# 決策地圖：一題一題做決定，直到路線清楚

工作大到一個對話裝不下、路線還看不清時用這支。它把路線畫成一張**地圖**，再一題一題解地圖上的**決策票**，直到沒有東西要決定、可以交給拆票。

**這支產出決定，不產出成品。** 想直接動手做，通常代表已經走到地圖邊緣，該交給 `to-tickets` 拆成施工票了。

## 1. 先讀私有擴充

照 [私有擴充](${CLAUDE_PLUGIN_ROOT}/references/private-extension.md) 的三步讀這支 skill 的補充（skill 名 `wayfinder`）：

1. 用 Bash 跑這一條，整條逐字照抄，不加引號、不接 `||`／`&&`、不改寫成 `echo`、`test` 或其他寫法：`printenv GITHUB_WORKFLOW_PRIVATE_DIR`
   - `printenv` 退出碼 1 且沒有輸出＝未設定；其他情況（被權限擋、工具錯誤、沒跑成）→ 停下告訴擁有者，不當成未設定。
2. 未設定 → 回報「私有擴充：未設定」，照本體做。**不讀任何私有檔。**
3. **有值才讀私有檔**：用 Read 讀 `<值>/wayfinder.md`。
   - 讀到 → 回報「私有擴充：已讀 wayfinder.md」，內容當補充規則，與本體一起遵守。
   - 讀不到 → 停下，告訴擁有者讀不到哪個路徑，不要照本體繼續。

## 2. 地圖＝SPEC 票

- **地圖就是 SPEC 票**，決策票是它的子票。不另立地圖標籤、不另立票種。
- SPEC 的內文照 [SPEC 範本](${CLAUDE_PLUGIN_ROOT}/skills/to-spec/references/spec-template.md) 寫；地圖用到其中三段：
  - **已經做的決定**：每解完一張決策票加一行 `[票名](連結)：一句結論`。SPEC 是索引，不是倉庫——細節只留在子票，SPEC 不重抄。
  - **尚未定義**：看得到、但還無法寫成明確問題的事。開著的決策票不列在這裡（它們是子票，用查詢就看得到）。
  - **刻意不做的事**：判定超出這次目的地的事，每條一句理由＋連結。
- 標籤照 [labels.md](${CLAUDE_PLUGIN_ROOT}/references/labels.md)：SPEC 掛類型＋優先；決策票是一般票，掛三組。

### 決策票

- **標題前綴**：`[決定]`（要選一個做法）、`[查證]`（要查出一個事實，決定才做得了）、`[操作]`（要先做一件事，決定才做得了，例如開通權限、搬資料看形狀）。
- **內文寫三樣**：要解決的問題；**擁有者在場：要／不要**；解完時要留下什麼（答案、查到的事實、做完的紀錄）。
- **擁有者在場：要** 的票，只在擁有者本人在場、親口回答的對話裡解。**不替擁有者回答**：可以提問、可以附上自己建議的答案，但答案一定要擁有者本人講；自己提問又自己作答＝這張票沒有解。
- 一張票的大小以一個對話解得完為準。
- 先後用原生 `blocked-by`。擋住它的票全部關了＝可以解；**可以解的範圍**＝SPEC 底下開著、沒被擋、沒人認領的子票。

### 霧與票的分界

判準是**現在能不能把問題講精確**，不是現在能不能回答：

- 問題已經講得精確（就算被擋住、暫時不能解）→ 開成決策票。
- 還講不精確 → 寫進「尚未定義」，不要預先切成票大小；之後一塊可能變成好幾張票，也可能一張都不用。

## 3. 畫地圖

擁有者帶著一個還模糊的想法來時：

1. **先定目的地**：這張地圖要走到哪——一份可以拆票的 SPEC、一個要先鎖定的決定，或一次就地完成的改動。目的地決定範圍，先定它。要談的地方用質問類 skill 談，不要自己替擁有者定。
2. **看出可以解的範圍**：橫向掃過整個題目，列出還沒做的決定與現在就能開始的第一步。**掃完發現沒有霧**（路線已經清楚、一個對話做得完）→ 不需要地圖，停下問擁有者要怎麼進行。
3. **建地圖**：還沒有 SPEC → 用 `to-spec` 開（已經做的決定先空著、霧寫進「尚未定義」）。已經有 SPEC → 在它底下畫。
4. **開現在講得精確的決策票**：用 `--parent <SPEC 號>` 掛成子票；全部開完再**第二輪**設 `blocked-by` 與互相引用（票要先有號碼才能互指；不要寫佔位的 `#<n>`，它會自動連到無關的票）。
5. 停：畫地圖是一個對話的工作，這個對話不解任何一張票。

開 SPEC 與開票由指揮台做（見入口 skill 的角色表）。

## 4. 走地圖

擁有者帶著一張地圖（SPEC 的網址或號碼）來時，票可以不指定：

1. **讀地圖**：只讀 SPEC 內文（低解析度的全貌），不把每張子票的內文都讀過；需要時再讀相關的票。
2. **選票**：擁有者指定了就用那張；沒指定就取可以解的範圍裡的第一張。
3. **認領**：開始任何工作之前先認領，讓同時在跑的其他對話跳過它。認領照 repo 設定的施工狀態記法掛狀態、掛這台的機器標籤，在票上留一則附署名的留言（格式以 labels.md 第三節為準）。**不用 assignee 認領。**
4. **照前綴解**：`[決定]` 用質問類 skill 和擁有者談；`[查證]` 查一手資料，結果附來源、SHA 或指令；`[操作]` 能自己做的自己做，做不了的給擁有者一份精確的清單。擁有者在場：要 的票，照第 2 節不替擁有者回答。
5. **解完四步**：
   1. 在票上**留言寫答案**（查到的事實、做完的紀錄、之後的票會用到的數字一起寫）。
   2. **關票**。
   3. 在 SPEC「**已經做的決定**」加一行：`[票名](連結)：一句結論`。
   4. **開出新冒出的票**，並把已經能講精確的霧從「尚未定義」移走，讓它只活在新票上。開票由指揮台做；這個對話不是指揮台 → 在 SPEC 留言列出要開的票，由指揮台開。
6. 答案顯示某張票（這張或別張）超出目的地 → 關掉它，在「刻意不做的事」加一行理由＋連結，不寫進「已經做的決定」。答案讓地圖其他部分失效 → 更新或關掉那些票。

SPEC 內文只有指揮台改；其他人在 SPEC 留言，由指揮台謄進內文。

## 5. 施工中冒出的事

施工者看到計畫外的新事，不開票：記在 SPEC 留言，由指揮台寫進「尚未定義」，在做決定時統一處理（要做的開票、不做的寫進「刻意不做的事」）。資安、個資、正式環境壞掉這類不能等的，在 SPEC 留言標 🔴，指揮台當場開票。

## 6. 講票與對話長度

- **講票用名稱**：給擁有者看的回覆、SPEC 的「已經做的決定」用票名，號碼做成連結；給機器的（`blocked-by`、指令參數）照舊用號碼。一整排裸號碼讀不懂，名稱一眼看得懂。
- **一個對話解幾張不硬性規定**：同主題可以連著解。換主題時看對話長度，太長就先寫交接（`handoff`），再開新對話接著走。
- 同時可能有別的對話在解同一張地圖的其他票，改 SPEC 前先重讀一次最新內文。
