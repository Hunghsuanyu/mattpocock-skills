# 寫交接：發在工作所在 repo 的指揮台

把這個對話交給下一個對話（換對話、換機器、交給別人）時用。交接以**留言**發在這件工作所在 repo 的協作指揮台上：接手的人本來就會讀那個 repo 的指揮台，放別處要多跑一趟，原 repo 的指揮台也會缺一段紀錄。

參數＝下一個對話要做什麼。內容依它裁剪：只留接手這件事用得到的。

## 1. 先讀私有擴充

照 [私有擴充](${CLAUDE_PLUGIN_ROOT}/references/private-extension.md) 的三步讀這支 skill 的補充（skill 名 `handoff`）：

1. 用 Bash 跑這一條，整條逐字照抄，不加引號、不接 `||`／`&&`、不加重導向、不改寫成 `echo`、`test` 或其他寫法：`printenv GITHUB_WORKFLOW_PRIVATE_DIR`
   - `printenv` 退出碼 1 且沒有輸出＝未設定；其他情況（被權限擋、工具錯誤、沒跑成）→ 停下告訴擁有者，不當成未設定。
2. 未設定 → 回報「私有擴充：未設定」，照本體做。**不讀任何私有檔。**
3. **有值才讀私有檔**：用 Read 讀 `<值>/handoff.md`。
   - 讀到 → 回報「私有擴充：已讀 handoff.md」，內容當補充規則，與本體一起遵守（例如：完全沒有 repo 的工作放哪一張個人指揮台）。
   - 讀不到 → 停下，告訴擁有者讀不到哪個路徑，不要照本體繼續。

## 2. 決定放哪

照順序找，找到就停：

1. **擁有者說了「只寫檔、不發」** → 只寫檔（第 4 節），告訴擁有者路徑，不呼叫任何發留言的指令。
2. **先找這件工作歸屬的 repo**：從參數、這個對話碰過的票與分支判斷。判斷不出來、或同時像是兩個 repo 的工作 → 問擁有者，不要猜。
3. **找那個 repo 的協作指揮台**：標題以「協作指揮台」開頭、還開著的票。
   ```bash
   gh issue list -R <owner>/<repo> --state open --search "協作指揮台 in:title" --json number,title
   ```
   - 只認標題**開頭**是「協作指揮台」的；對到一張 → 發在那張。
   - 對到兩張以上 → 列出來問擁有者發哪張。
   - 擁有者已經在參數或對話裡指名了指揮台 → 用指名的那張，仍要 `gh issue view` 確認標題開頭是「協作指揮台」；不是 → 停下問。
4. **那個 repo 沒有指揮台**：
   - 擁有者自己的個人 repo → 先問擁有者「要不要在這個 repo 開一張協作指揮台」，同意了才開（標題以「協作指揮台」開頭），再發在那張。沒同意 → 只寫檔。
   - 不是擁有者自己的 repo → 不自己開票，問擁有者放哪。
5. **真的找不到歸屬 repo** → 私有擴充指定的個人指揮台。私有擴充沒有指定 → 只寫檔，告訴擁有者路徑。

**一律用留言，不改指揮台內文。** 內文只有指揮台那一軌改；留言多軌同時發也不會互蓋。

交接留言**不需要擁有者說「發」**：交接本來就是要發在指揮台的。這跟「對同仁的分流回覆要擁有者明說『發』」是兩件事，不要混用。

## 3. 寫之前先重讀

交接最常出的錯是把「當下以為的」寫成事實，下一個對話照單全收、不會重查。所以每條狀態都要分成兩種：

- **讀回過**：這次寫交接時，用工具把它重讀了一次（`gh issue view`、`gh pr view`、`git rev-parse`……），結果就是寫的那樣。行尾標 `（YYYY-MM-DD HH:MM 讀回）`，時間用 `date '+%Y-%m-%d %H:%M'` 取，不憑印象寫。
- **其他一律**標 `（未查證）`：包括「對話稍早看過、這次沒重讀」「跑不了 `date` 拿不到時間」「被權限擋了讀不到」。

不確定算哪一種 → 標「未查證」。

## 4. 交接稿格式

先寫成檔，再發。檔案用 Write 寫到擁有者指定的路徑；沒指定就寫到這個對話的暫存目錄（沒有就寫系統暫存目錄），**不寫進 repo 的工作樹**。

第一行固定是 `# 交接：<下一個對話要做什麼>`（找「前一則交接」就靠這一行）。之後是固定六段，標題用 `## ` 加下面的名稱、照這個順序，不增不減、不改名：

```markdown
# 交接：<下一個對話要做什麼>

## 交出的機器與 session
## 前一則交接
## 等擁有者
## 進行中的票
## 建議接手先用的 skill
## 規則沿用
```

各段寫什麼：

| 段 | 內容 |
|---|---|
| 交出的機器與 session | 哪一台機器（`hostname`）、哪個 session；拿不到就寫「未查證」 |
| 前一則交接 | 同一張指揮台上一則以 `# 交接：` 開頭的留言的連結；沒有就寫 `無` |
| 等擁有者 | 要擁有者做的事，**照順序、一次一件**：排第一的是現在就要做的那件，後面的等前一件做完才輪到 |
| 進行中的票 | 每張一行：票名做成連結＋分支＋HEAD 的完整 SHA（`git rev-parse` 取，不從短碼補）＋現在卡在哪 |
| 建議接手先用的 skill | 下一個對話一開始該用 Skill 工具叫哪幾支，每支一句為什麼 |
| 規則沿用 | 這個對話裡講定、下一個對話要繼續遵守的做法；有出處的給連結 |

**狀態列的固定寫法**（「等擁有者」「進行中的票」兩段）：

- 每條一行、以 `- ` 開頭，行尾固定是 `（YYYY-MM-DD HH:MM 讀回）` 或 `（未查證）`，標記之後不再接任何字。
  ```markdown
  - [登入頁跑版](<票的網址>)｜分支 fix/login-layout｜<40 碼 SHA>｜等審查（2026-01-02 09:30 讀回）
  - 決定登入頁要不要保留舊版樣式（未查證）
  ```
- **某段沒有任何一條時，寫一行 `無`**——不帶 `- `、不加標記。寫成 `- 無` 會被當成一條缺標記的狀態列。
- 其他四段不是狀態列，不加標記；但裡面有講到狀態的句子，同樣寫明讀回或未查證。

**只給連結、不重抄**：已經在票、PR、規格、commit 裡的內容，只給連結或 SHA。交接只補「那些地方沒寫、下一個對話又需要」的東西：為什麼這樣做、試過什麼不行、卡在哪。

## 5. 發之前

1. **遮蔽**：照 [redaction.md](${CLAUDE_PLUGIN_ROOT}/skills/handoff/references/redaction.md) 把密鑰、權杖、密碼、個資換掉。指揮台的同仁看得到，**私事一律不寫**（不是遮，是整句不寫）。
2. **自己讀一遍**：用 Read 讀回剛寫好的檔，逐條問「這句是讀回過的，還是我以為的？」——只是假設的降級成「未查證」；檢查六段標題與順序、狀態列的標記、遮蔽有沒有漏。改完再讀一次。
3. **不把交接內容內插進 shell 指令**：反引號、`$(...)` 會被執行或吃掉，長文還會被靜默截斷。內容只活在檔案裡，指令只帶檔名。

## 6. 發

```bash
gh issue comment <指揮台票號> -R <owner>/<repo> --body-file <交接稿檔案>
```

- 一則交接只發一次、只發在第 2 節決定的那一張；不同時發到別處。
- 只發留言：不改指揮台或任何票的內文、標籤、狀態，不開票（第 2 節第 4 點擁有者同意的那一張除外）。
- 發完把留言的網址告訴擁有者；只寫檔的，告訴擁有者檔案路徑，並提醒暫存目錄會被系統清掉。

## 7. 界線

- 除了第 6 節那一則留言，不發任何訊息（聊天、郵件、推播都算）。
- 交接是給下一個對話讀的，不是給擁有者的報告；接手讀不到的東西（只活在這個對話裡的推論）要寫進來，已經寫在別處的不要重抄。
- 界線外的判斷（放哪判斷不出來、私有擴充與本體衝突）攤出來問擁有者，不要自己決定。
