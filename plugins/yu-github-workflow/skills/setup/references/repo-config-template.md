# repo 設定範本（`docs/agents/github.md`）

每個 repo 一份，只寫這個 repo 特有的事；通用規則在 plugin，不抄進來。其他 skill 只讀固定標題「機器讀的欄位」底下那一個 `text` 區塊。

## 區塊的形狀

- 固定標題 `## 機器讀的欄位`，底下第一個 `text` 區塊。
- 一行一個欄位，`<欄位名>` 後接半形冒號與一個空格，再接值。欄位名逐字照下表，順序照下表。
- **每個欄位都要出現**。用不到的寫下表的空值（`不適用`、`無`），不刪欄位、不留空白。
- 程式 repo（票開在別的 repo）的專案層欄位寫 `見 <owner>/<repo>`，指到放票的 repo。
- **讀不到不等於過關**：開票自檢（`ticket-check.sh`）讀不到這份設定、缺欄位、或「只檢查誰開的票」是 `未設定` 時，相關的格印 `??` 開頭的行、整段略過，**退出碼不受影響，仍可能是 0**。退出碼 0 只代表沒有 `NG`；有沒有每一格都查到，要看輸出裡有沒有 `??`。看到 `??` 就把這份設定補齊再跑。

## 欄位

| 欄位 | 值的寫法 | 值從哪來 | 誰讀 |
|---|---|---|---|
| 票開在哪個 repo | `本 repo`，或 `<owner>/<repo>` | 預設本 repo；使用者講明或私有擴充指定才改 | 所有 skill |
| 誰按合併 | `擁有者`，或 GitHub 帳號（多個用逗號） | 第 2 題 | 給人看，skill 不讀、不影響行為（這套流程的 skill 一律不合併進預設分支） |
| 部署線 | `不部署`／`合併即部署`／`推 main 即部署`／`手動`，四選一 | 第 3 題 | 給人看，skill 不讀：`setup` 寫入時拿它和 `.github/workflows/` 對照，其他 skill 不讀這個欄位。部署路徑的細節寫在下面「部署線」段 |
| 施工狀態記法 | `labels` 或 `project`，就是 `labels-setup.sh --status` 的值 | 第 1 題 | 施工、驗證、建標籤 |
| Project 所在 | `<owner>` 加 Project 號碼；`labels` 記法寫 `不適用` | 第 1 題 | 換狀態 |
| Project ID | Project 的 node id；`labels` 記法寫 `不適用` | 指令表「Project」那列 | 換狀態 |
| Status 欄位 ID | Status 欄位的 id；`labels` 記法寫 `不適用` | 指令表「Project」那列 | 換狀態 |
| Status 選項 ID | `<選項名>=<id>`，多個用逗號；`labels` 記法寫 `不適用` | 指令表「Project」那列 | 換狀態 |
| 機器標籤名 | 標籤名，多個用逗號，就是 `--machine-labels` 的值；不用就寫 `無` | 私有擴充；沒有就 `無` | 施工、建標籤 |
| 等待擁有者的標籤名 | 標籤名，就是 `--owner-wait-label` 的值 | 私有擴充；沒有就 `等擁有者` | `pr`（開完 PR 掛這個標籤）、`setup`（建標籤時帶給 `labels-setup.sh`） |
| 只檢查誰開的票 | GitHub 帳號 | 私有擴充；沒有就讀目前 `gh` 登入的帳號，讀不到寫 `未設定` 並告知擁有者 | 開票自檢 |
| 特殊禁忌 | 一句話；細節寫在下面「特殊禁忌」段；沒有就寫 `無` | 第 4 題 | `implement`（開工時讀）、`review`（列進寫法文件）、`pr`（開 PR 前讀） |

## 範本

照抄以下整段進 `docs/agents/github.md`，再把值換成這個 repo 的。下面填的是「不進 Project、擁有者按合併、不部署、沒有禁忌」的值。

~~~markdown
# GitHub 工作流設定

這份是這個 repo 怎麼用 GitHub 工作流，由 `setup` 產生。改運作方式時，在同一個 PR 改這份。

## 機器讀的欄位

```text
票開在哪個 repo: 本 repo
誰按合併: 擁有者
部署線: 不部署
施工狀態記法: labels
Project 所在: 不適用
Project ID: 不適用
Status 欄位 ID: 不適用
Status 選項 ID: 不適用
機器標籤名: 無
等待擁有者的標籤名: 等擁有者
只檢查誰開的票: 未設定
特殊禁忌: 無
```

## 部署線

（部署線不是「不部署」時，寫出部署路徑的全集：哪一支 workflow、Pages、外部服務接在 main 上的建置觸發。）

## 特殊禁忌

（「特殊禁忌」不是「無」時，逐條寫：什麼不能做、例外的是哪一支 workflow 或哪一條規則、為什麼。）
~~~
