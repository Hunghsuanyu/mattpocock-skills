# 多子代理並行：隔離、量測污染與工具

## 暫存工具與副本：三條同一科

多個子代理同時跑時，量測工具（突變腳本、還原用的原始副本、log）會互相干擾，而且**污染的是量測結果、不是程式碼**：diff 裡看不到、測試也不會變紅，兩邊都沒有錯誤訊息。

- **(a) 放各自的工作樹或各自的子目錄，限定檔名**：不在共用暫存目錄的頂層寫 `mutate.py`、`a.log` 這類通用檔名。兩個子代理寫了同名工具會互相覆蓋，還原時跑到的是另一個子代理的腳本。
  - 子代理的 `isolation: worktree` 不隔離共用暫存目錄。
  - `.git/info/exclude` 跨工作樹共用，也不是逃生口。
- **(b) 放在受測樹外面**：量測用的副本放進受測的工作樹根目錄，會被掃描 repo 內檔案的測試撈進去，讓測試因為儀器本身而紅。
- **(c) 跑的時候不改自己的工具**：shell 腳本執行到一半被改寫，shell 會從錯的位元組位移續讀，尾巴變成亂碼指令、log 被截斷。抓得到它的通常是「退出碼與結果數互相矛盾」，不是錯誤訊息。

懷疑受到污染時，把可能受影響的那幾輪作廢重跑，不要用時間戳去論證它們乾淨。長跑的量測可以每隔幾秒記一次受測檔的雜湊，整輪只能有一個值。

## worktree 隔離

- 一張票一個工作樹，從整合分支開。
- `isolation: worktree` 只隔離主要工作目錄那個 repo；子代理要動其他 repo，自己對那個 repo `git worktree add`。
- 收尾用 `git worktree remove --force <路徑>` 拆，拆完看 `git worktree list`。

## 並行的界線

- 只共用同一條部署線不擋施工：分支可以並行，合併與部署一次一張。
- 改同一個檔、同一份共用設定，或有語意上的先後 → 由 `blocked-by` 排先後；同一份 context 的票合成一個子代理。

## 子代理之間怎麼溝通

- **票的留言是正式紀錄**。SendMessage 只用來提醒「去看某張票的留言」，因為訊息不會留下來。
- 等 CI 跑完用 Monitor 或 `gh run watch`，不要一直重查。

## 評估過、暫不採用：Claude Code Workflow

把施工＋驗證寫成一支具名 Workflow 評估過，暫不採用：它在背景跑、中途不能停下來等擁有者輸入，跨好幾天或有人工步驟的流程接不上，而施工與驗證讀同一張票，票上的檢核寫錯時兩邊會一起錯。同一批工作出現多張要換廠牌外審的程式票時再評估。
