# 換廠牌外審：怎麼送、怎麼確認沒送多

外審用在兩個地方：改動模式裡驗證等級是 `重驗證-外審` 的改動，以及規格模式的整批票。送審的腳本、旗標與核可流程放在私有擴充；這裡只放不分環境都成立的規則。

## 為什麼要換廠牌

同一個模型審自己（或同源模型）寫的東西，抓得到錯字與遺漏，抓不到「票本身寫錯了」——施工與驗證讀的是同一張票，票上的判準錯了，兩邊會一起錯、一起綠。那一塊只能靠換一家模型、用對抗式的提示詞來質疑。

## 只送副本

- 把要審的內容導出成純文字副本，**只送副本**：不給 repo 路徑、不把外部模型的工作目錄設在 repo 裡、用完即刪。
- 外部工具的「唯讀模式」**只擋寫入、不擋讀取**：它仍然讀得到工作目錄以外、本機上任何它想讀的檔。這一點沒有機械強制點，只能靠「手上本來就只有副本」。

## 確認「沒把 repo 交出去」：量路徑參數，不量工作目錄

送審後要確認外部模型沒有讀到 repo 或本機其他檔時：

- **量它執行過的每一條指令裡的路徑參數**（讀了哪些檔、列了哪些目錄）。
- **不要量工作目錄**：每一段都在暫存目錄裡跑、全部綠燈，照樣可能有幾段在讀暫存目錄以外的檔。工作目錄不告訴你它讀了什麼。
- **執行區塊的數量不是指標**：同一條指令、同一個版本、同樣規模，跑兩次的區塊數可以差好幾倍。
- **不要寫成「整份紀錄不得出現某段路徑字串」**：送審的票內文自己就可能寫著那段字串，這種判準必然假紅。

## 外部模型的修正不直接採用

每一條先用自家模型對照專案目標與程式邏輯複核，符合才改；不符合的留言寫「不採納＋為什麼」。步驟見 `review` 本體第 5 節。
